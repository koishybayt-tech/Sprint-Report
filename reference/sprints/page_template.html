Ресурсы по руководителям

Какую долю всех сотрудников занимает каждый руководитель в текущих спринтах. Если человек работает в проектах нескольких руководителей, он делится между ними пропорционально числу своих задач в спринте (например, 6 задач у одного и 2 у другого — это 0,75 и 0,25 человека). Уволенные и задачи без исполнителя не учитываются. Нажмите на строку руководителя, чтобы увидеть, сколько ресурсов занимает каждый его проект.

Отпуска, больничные и отгулы: задачи, которые никто не закроет

Сотрудник в отпуске или на больничном, а на нём висят задачи спринта в бэклоге, в работе или в реворке. Они не закроются, пока его нет, и план спринта не выполнится, если их не переназначить. Отпуска (трудовой и без содержания) — из Bitrix, больничные и «отпросился» (от 2 часов за день) — из Telegram-группы «Adata Group». Метка «конец спринта» — отсутствие попадает на последние 2 дня спринта, где у сотрудника есть незакрытые задачи.

Сотрудники, у которых заканчиваются задачи

Считается всё, что сотрудник ещё может взять в работу во всех проектах: Бэклог + В работе + Реворк. Задачи на ревью и в тестировании не считаются — они ждут других. Тимлиду этих людей нужно делегировать задачи. В колонке «У кого взять задачи» — коллеги по тем же проектам с бэклогом больше порога: только с той же ролью (фронт у фронта, бэк у бэка и т.д.) и ПМ, задачи которых может взять любой. ПМ — сотрудник с ролью Project Manager или руководитель проекта (учитывается бэклог только в его собственных проектах). Если роль сотрудника в Jira не указана, показываются только ПМ. Число — их бэклог в общих проектах, нажмите, чтобы открыть эти задачи.

Сотрудники с перегрузом в бэклоге

У кого в статусе «Сделать» скопилось слишком много задач спринта по всем проектам. Эти задачи стоит раздать. В колонке «Кому отдать» — сотрудники из тех же проектов, у которых заканчиваются задачи (по правилам вкладки «Нужны задачи»), с той же ролью. Если перегружен ПМ или руководитель проекта, предлагаются все, у кого заканчиваются задачи, — задачу ПМ может взять любой.

Сотрудники, которые тормозят проект

Сотрудник работает над задачами одного руководителя, а задачи другого руководителя у него лежат в бэклоге и не двигаются (нет ни одной задачи в работе, ревью или реворке). Из-за этого проект второго руководителя стоит.

Тимлиды, которые держат бэклог на себе

Тимлиды из группы adata-team-leads: сколько задач спринта в статусе «Сделать» назначено на них самих. Такие задачи не распределены — команда не видит весь объём работы. Рядом — сколько сотрудников в проектах тимлида остаются без задач.

Загрузка QA

По полю «Тестировщик». У Алмабаева Асанәлі задачи почти во всех проектах — похоже, это значение поля по умолчанию, а не реальное назначение.

Узкие места

Незакрытые задачи в статусах Blocked, Need Rework, «Требует уточнения», а также любые задачи без обновлений больше 30 дней.

Стабильность спринтов

Сколько задач перенесено из прошлых спринтов, сколько создано после старта текущего и сколько помечено внеплановыми.

Качество

Доля задач типа «Ошибка» в спринте и задачи, вернувшиеся на доработку.

Готовность к релизу

Процент готовности спринта (доля задач в «Готово») и задачи на финише: Code review, Test, Ready for deploy / In Staging. Задачи в Test разделены по полю «Тестировщик»: QA (и пустое поле), PM, тимлид / остальные.

Следующий спринт

Готов ли следующий спринт к старту. Следующий ищется по названию текущего с номером +1 (например, «Адата Комплаенс 2026-19» → «2026-20»). «Перейдёт» — незакрытые задачи текущего спринта. «Без задач в следующем» — кто работает в текущем спринте проекта, но в следующем у него задач нет.

Качество данных в Jira

Чего не хватает, чтобы строить отчёты по трудозатратам и срокам.

Данные выгружены из jira.adata.kz через REST API. Ссылки открывают актуальные задачи в Jira. Чтобы обновить срез, попросите Claude выгрузить данные заново.
