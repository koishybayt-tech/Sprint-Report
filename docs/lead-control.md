# Модуль «Проекты руководителей · контроль спринта»

Это перенос дашборда «Проекты руководителей · контроль спринта» из артефакта Claude в сервис Adata Reports. Макет: `design/prototypes/lead-control.html`. Это код страницы из артефакта, и он работает только внутри артефакта: стили на CSS-переменных, данные через объект `dash`. Использовать его нужно как образец разметки, текстов, колонок и правил, а не как готовый код.

## Что показывает
Страница для руководителя: что мешает его открытым спринтам прямо сейчас.

**Фильтры:**
- руководитель — чипы, в URL `?lead=`;
- проект — «Все проекты» или конкретный, в URL `?proj=`;
- активная вкладка — в URL `?tab=`.

**Руководители и проекты** (таблица `lead_projects`, редактируется в «Настройках»; проект можно дополнительно назначить пользователю сервиса — `user_id` — тогда он видит его как свой, например ПМ проекта):

| Руководитель | Проекты |
|---|---|
| Қойшыбай Темірлан | AC (Комплаенс), EDO (ЭДО), DO (Digital Office), SUP (Снабжение), AML |
| Тажибаев Нурлыбек | ADTC (Counterparty), AIJ (AI Адвокат), AL (Landing), AAP (Admin Panel), API (Adata API) |

**Плитки-счётчики** (по клику открывают свою вкладку):
1. **Заблокированы** — задачи в статусе Blocked.
2. **Долго в работе** — 5 и более дней в текущем статусе.
3. **Тормозят задачи** — сотрудники, у которых здесь задачи стоят, а у других руководителей двигаются.
4. **Дизайн или бэк готов, а продолжения нет** — в текущем спринте нет задачи на фронт или бэк.
5. **Долго на тесте** — 3 и более дней в статусе Test.

**Вывод под плитками:**
> «X из Y заблокированных задач ждут задачу, которая ещё не начата; с Z блок можно снимать. Сотрудников, у которых здесь задачи стоят, а у других руководителей двигаются: N.»

Внизу полоса статусов по каждому открытому спринту. Порядок статусов: Готово, Ready for deploy, Test, Code review, В работе, Need Rework, Blocked, Сделать.

## Подчинённые
Руководитель пользователя (поле «Руководитель» в «Настройки → Пользователи») видит в этой странице своих подчинённых и подчинённых подчинённых: каждый — отдельный чип «Руководитель» со своими проектами (назначенными пользователю в «Руководители и проекты» или по его сотруднику-руководителю из Jira).

## Фильтры по человеку и выгрузка в Excel
- На каждой вкладке есть фильтр «Исполнитель» («Сотрудник» на вкладке «Тормозят задачи»), на вкладке «Долго на тесте» — ещё «Тестировщик». Списки со счётчиками, фильтры связаны между собой и с остальными (поиск, пороги, приоритет), в адресе: `who`, `tst`.
- «Скачать в Excel» выгружает таблицу ровно в том виде, как она на экране: с фильтрами, поиском, порогами и сортировкой. Лист «Параметры» фиксирует, с какими фильтрами сделана выгрузка. API — `POST /api/v1/lead-control/export`.

## Данные
Источник — Jira, задачи открытых спринтов проектов руководителя: `cf[10104] in openSprints()` и `expand=changelog`. Дополнительно нужны связи задач (`issuelinks`) и поле «Тестировщик» (`customfield_10902`).

**Роль задачи:**
- по префиксу названия: «Дизайн -», «Фронт -», «БЭК -»/«Бэк -», «ИИ -»;
- если префикса нет — по должности исполнителя (`customfield_11101`);
- «ИИ» считается бэком.

**Дни в статусе:**
- считаются от последнего перехода в этот статус по changelog;
- «с начала» — с момента, когда задачу взяли в работу: первый переход в «В работе» после последнего возврата в «Сделать» (круги ревью и доработки его не сдвигают). Имена статусов в истории Jira английские (In Progress, To Do, Done) — перед расчётом они приводятся к русским (`CanonStatus`).

## Вкладки и правила

### 1. Заблокированные задачи (`blocked`)
**Колонки:** Задача, Исполнитель, Роль, Дн. в Blocked, Что с блоком, Ждёт задачу, Её роль, Её статус, Её исполнитель, Не начата, Блокирующие задачи (статус, когда ушла на тест), Название, Прочие связанные.

**Кто кого ждёт:**
- фронт ждёт связанные задачи дизайна и бэка;
- бэк (и ИИ) ждёт только дизайн;
- дизайн никого не ждёт.

Связи берутся из Jira links.

**Колонки «Ждёт задачу» и «Что с блоком»:**
- **«Ждёт задачу»** — первая блокирующая задача, ещё не дошедшая до теста. Сначала проверяется бэк, потом дизайн.
- **«Не начата» = да** (строка красная) — эта задача в статусе «Сделать».
- **«Можно снимать блок»** — все блокирующие задачи уже на Test или дальше. Показывается с датой, когда последняя из них ушла на тест (зелёный).
- **Иначе** — «Ждёт …».

Сортировка по умолчанию — дни в Blocked по убыванию.

### 2. Долго в работе (`in_work`)
**Статусы:** В работе, Code review, Need Rework.

**Колонки:** Задача, Статус, Исполнитель, Роль, Дн. в статусе, Дн. с начала, Всего в статусе, Возвратов (в Need Rework), Спринтов, Название.

**Показ и подсветка:**
- по умолчанию только 5 и более дней, есть переключатель «показать все»;
- от 10 дней — красным, от 5 — оранжевым.

### 3. Сотрудники: задачи руководителя стоят, у другого двигаются (`people`)
Учитываются только действия самого сотрудника по changelog:
- «взял» — перевёл задачу в «В работе»;
- «завершил» — перевёл в Code review, Test или дальше.

**«Тормозит»** — у сотрудника есть задачи этого руководителя в статусе «Сделать», «В работе» или Need Rework без смены статуса 3 и более дней. При этом за последние 7 дней он брал и завершал задачи других руководителей чаще, чем делал что-то по задачам этого руководителя.

Тестировщики и ПМы не помечаются.

**Колонки:** Сотрудник, Роль, Сигнал, Стоят ≥ 3 дн., Открытых здесь, Его действия здесь за 7 дн., Последнее действие здесь (дн. назад), Взял у других за 7 дн., Завершил у других за 7 дн., Задачи здесь (дн. без движения), Другие проекты (руководитель) — действий, Что делал у других.

По умолчанию показываются только строки с сигналом. Ключ строки — (руководитель, сотрудник).

### 4. Дизайн или бэк готов, а продолжения нет (`gaps`)
Только задачи текущего спринта: готовые (Test или дальше) задачи дизайна и бэка без парной задачи на фронт и/или бэк.

**Как ищется пара:**
- по связи Relate;
- по одинаковому названию после префикса «Дизайн -» / «Фронт -» / «БЭК -»;
- по похожему названию — «похоже N%», проверить вручную.

**Приоритет:**
- «Будущий спринт» и «Высокий» — нет задачи на фронт (красный);
- «Проверить» — найдена только похожая задача, или бэк готов без фронта (оранжевый);
- «Низкий» — дизайн без бэка, дизайн-задачи без разработки, исправления ошибок.

Готовый фронт без бэка проблемой не считается.

**Фильтры:** приоритет, «чего нет» (нет фронта и бэка / нет фронта / нет бэка), тип (дизайн / бэк).

**Колонки:** Задача, Приоритет, Тип, Статус, Исполнитель, Чего нет, Проблема, Фронт, Бэк, Спринт, Название.

### 5. Долго на тесте (`testing`)
**Колонки:** Задача, Исполнитель, Роль, Дн. на тесте, Тестировщик, Дн. с начала, Спринтов, Баг, Название.

**Показ и подсветка:**
- по умолчанию только 3 и более дней;
- от 7 дней — красным, от 3 — оранжевым.

### Общее для таблиц
- Сортировка по клику на заголовок.
- Поиск по тексту.
- Ключи задач в любом поле — ссылки на `https://jira.adata.kz/browse/<KEY>`.
- В шапке «Данные из Jira обновлены: <дата время> (Алматы)».

## API (добавить в api/openapi.yaml)
- `GET /api/v1/lead-control/leads` — руководители и их проекты.
- `GET /api/v1/lead-control?lead=&project=` → `{updated_at, totals, sprints[], blocked[], in_work[], people[], gaps[], testing[]}`. Названия полей — как в колонках выше; snake_case, как в прототипе (`days_in_status`, `block_state` и т.д.).

## Доступ
Роли `admin` и `lead`. Руководитель по умолчанию видит себя, admin видит всех.

## Решения
Места, где описание допускает разные толкования; так сделано в `internal/leadcontrol` (каждое покрыто тестом).

**Данные**
- Задачи открытых спринтов приходят с `expand=changelog` при каждой синхронизации Jira (полной и инкрементальной), связи — `issuelinks` в `jira_issue_links`. История остальных задач года (для «Что делал у других») — из `reports sync jira-history`.
- В JQL ключи проектов берутся в кавычки: `DO` — зарезервированное слово Jira.
- Ключ строки на странице — `lead + key` (для «Сотрудников» — `lead + person`), как в макете.

**Роль задачи**
- Префикс названия узнаётся с любым разделителем: `-`, `–`, `—`, `.`, `:` (в данных встречается «БЭК. …», «Фронт. …»), без учёта регистра.
- Без префикса — по «Позиции разработчика» задачи: Frontend → Фронт, Backend и Data Engineer → Бэк, AI Engineer → ИИ, Designer → Дизайн, QA Engineer → QA, Project Manager → ПМ.
- «ИИ» в колонке «Роль» показывается как ИИ, а в правилах «кто кого ждёт» и поиске пары считается бэком.

**Статусы**
- Порядок процесса: «Сделать»/«Требует уточнения» → «В работе»/Need Rework → Code review → Test → Ready for deploy (и Production, In Staging) → «Готово»/In Production. Неизвестные статусы считаются разновидностью теста (как во всём сервисе). Blocked — вне шкалы.
- «На тесте или дальше» — Test и всё, что после него. Открытая задача — всё, кроме «Готово» и In Production.

**Дни**
- Целые дни (вниз) от момента перехода до времени расчёта.
- Нет перехода в текущий статус (задача так и создана) — дни от создания задачи.
- «Всего в статусе» — сумма всех заходов в текущий статус, включая текущий.
- «Когда ушла на тест» — последний переход из статуса до теста в Test или дальше.

**Заблокированные**
- Блокирующие — связанные задачи нужных ролей при любом типе связи (на деле блок почти всегда оформлен через Relate); связанные задачи других ролей — «Прочие связанные».
- Если связанных задач нужных ролей нет (в том числе у дизайна и у задач без роли) — «Что с блоком» = «Нет связанных задач, которых она ждёт» (оранжевым): пустой список не должен давать ложное «Можно снимать блок».
- «Ждёт» пишется как «Ждёт: бэк AC-11 (Сделать)»; «Не начата» — «да»/«нет», если есть кого ждать, иначе пусто.

**Сотрудники**
- Строки — исполнители открытых задач руководителя в его открытых спринтах.
- Действия — только «взял» (переход в «В работе») и «завершил» (переход из статуса до ревью в Code review, Test или дальше), сделанные самим сотрудником (автор перехода). «Его действия здесь» — такие действия в проектах руководителя за 7 дней; «Последнее действие здесь» — за всё время.
- «Другие руководители» — любые проекты не из списка руководителя; в колонке показывается их руководитель из `lead_projects`, иначе лид проекта в Jira.
- «Стоят ≥ 3 дн.» — задачи руководителя в «Сделать», «В работе» или Need Rework, у которых статус не менялся 3 дня и больше (без смен — от создания).
- «Тормозит» — есть такие задачи и (взял + завершил у других за 7 дн.) > (его действия здесь за 7 дн.). Других сигналов нет. Тестировщики и ПМ (по должности: QA/тест/test/manager/менеджер) не помечаются.

**Разрывы (дизайн или бэк готов, а продолжения нет)**
- Берутся задачи текущего спринта с ролью «Дизайн» или «Бэк»/«ИИ» в статусе Test или дальше. Дизайну нужны фронт и бэк, бэку — фронт.
- Пара ищется среди задач того же проекта: сначала связь Relate (в любую сторону), затем одинаковое название после префикса (без регистра и знаков), затем похожее — коэффициент Дайса по словам от 3 букв ≥ 0,5 («похоже N%»). Из нескольких точных совпадений берётся та, что в текущем спринте или уже на тесте/готова, затем в будущем спринте, затем в бэклоге.
- Пара «есть», если она в открытом спринте или уже на тесте/готова. В будущем спринте, в бэклоге вне спринта или найдена только похожая — пары нет.
- Приоритет (по порядку): исправление ошибки (тип «Ошибка») — «Низкий»; нашлась только похожая задача — «Проверить»; фронт есть, но только в будущем спринте — «Будущий спринт»; бэк готов без фронта — «Проверить»; дизайн: бэк есть, фронта нет — «Высокий»; дизайн без бэка и дизайн без фронта и бэка («дизайн-задача без разработки») — «Низкий».

**Полоса спринтов и итоги**
- Полоса — по каждому активному спринту проекта руководителя; «Готово» — «Готово»/In Production, Ready for deploy — Ready for deploy (и Production, In Staging), прочие статусы теста — Test.
- Итоги (плитки и вывод) считает сервер для «всех проектов» и для каждого проекта: «Долго в работе» — от 5 дн., «Долго на тесте» — от 3 дн., «Высокий» в разрывах — «Высокий» и «Будущий спринт».

**Доступ и обновление**
- admin видит всех руководителей; lead — только себя (его ФИО в справочнике сотрудников должно совпадать с `lead_projects.lead`), другие руководители в чипах ему не показываются.
- Расчёт хранится в `lead_control` и пересчитывается worker'ом после каждой синхронизации Jira (вне рабочего времени `SYNC_HOURS` синхронизаций нет — данные на вечер); если расчёта ещё нет, API считает его при первом запросе.

**Уведомления** (добавлено по запросу)
- События — после каждого пересчёта (то есть после синхронизации Jira): задача впервые попала в Blocked; с задачи впервые можно снимать блок; задача впервые оказалась в «Дизайн или бэк готов, а продолжения нет». Задача, которая ушла из списка и вернулась, даёт событие снова. Первый расчёт по руководителю только запоминает состояние — накопившееся не рассылается.
- Получатели — активные пользователи с ролью admin или lead, связанные с сотрудником-руководителем; какие события присылать — каждый настраивает в «Настройках» (по умолчанию все).
- Каналы: колокольчик в шапке сервиса; личный Telegram-бот руководителя (создаёт сам в @BotFather, токен вставляет в «Настройках», привязка — по одноразовой ссылке). Нужен `SECRETS_KEY` на сервере.
- «Создать продолжение» — ссылка на форму создания задачи в Jira (тот же проект и тип, название «Фронт - …», если нет фронта, иначе «БЭК - …»; в описании — ключ исходной задачи). Сервис задачи в Jira не создаёт: токен Jira — только на чтение. Связь Relate руководитель ставит сам.
- «Игнорировать» (в боте и на странице) — продолжение не нужно: задача скрывается из «Разрывов» и итогов, больше не уведомляет; список скрытых — под таблицей, оттуда можно вернуть.
