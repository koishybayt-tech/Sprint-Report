# Метрики и формулы

Источник истины — текущие дашборды. Если формула ниже неясна, смотреть код в `reference/` (указан в скобках) и переносить 1-в-1.
Все «сегодня/вчера» считаются в `Asia/Almaty`. Рабочий день: пн–пт, 09:00–18:00, минус `holidays`.

## 1. Статусы Jira → группы
| Группа | status.id | Смысл |
|---|---|---|
| `todo` (бэклог) | 10100 «Сделать» | |
| `wk` | 10011 «В работе» | |
| `cr` | 10008 Code review | |
| `rw` | 10000 Need Rework | |
| `dn` | 10001 «Готово» | |
| `ts` | всё остальное | Test, In Staging, Ready for deploy, In Production, Blocked, «Требует уточнения» |

## 2. Спринт проекта (`reference/sprints/inc.js`, вкладки «Статус спринтов», «Готовность к релизу»)
Берутся задачи `cf[10104] in openSprints()`. По проекту — активный спринт (state=ACTIVE).
- `t` — задач всего; `todo, wk, cr, rw, ts, dn` — по группам.
- `ready% = dn / t`.
- `time% = (сегодня − start) / (end − start)`, обрезано 0…100.
- **Отставание** = `time% − ready% > 25 п.п.` → красный.
- `left` = дней до `end`; `< 0` → «Не закрыт · N дн.»; `≤ 3` → жёлтый.
- `carry` — незакрытые задачи, бывшие ≥ 2 спринтах (`len(sprints) > 1`).
- `add` — созданы после `startDate` активного спринта.
- `unpl` — поле план (`cf 11204`) = «Внеплановая».
- `created_daily` — поток новых задач: задачи, лежащие сейчас в активном спринте проекта и созданные после его старта, по календарным дням (Алматы) от даты старта до min(сегодня, конец спринта); из них внеплановые (`unpl`). Сумма ряда = `added`. Показывается во вкладке «Стабильность» («Динамика созданных задач в спринте»).
- `bug` — тип «Ошибка»; `blk` — статус Blocked; `stale` — не done и `updated` > 14 дн.
- `rdy` — статусы Ready for deploy / In Staging; `tst` — статус Test.
- `h` — сумма `timespent`, часы.
- Самая старая незакрытая задача (`PX`) — ключ и возраст в днях; число незакрытых перенесённых.
- **Test по тестировщику** (`cf 10902`): QA Engineer или пусто / Project Manager / остальные (тимлид и т.д.).

## 3. Люди (`AX` в inc.js)
Строка на (исполнитель, проект): `t, todo, wk, cr, rw, ts, dn, bug`, бэклог старше 7 дн., дни с последнего движения в работе / по любой незакрытой, возраст самой старой в бэклоге.
- **Нужны задачи**: `todo + wk + rw ≤ N` (N по умолчанию 2) по всем проектам. Исключаются: тимлиды (группа `adata-team-leads`), Project Manager, QA Engineer (если не включено «показать всех»), сейчас отсутствующие, **неактивные пользователи Jira**. «У кого взять» — коллеги из общих проектов с той же ролью (по `cf 11101`) и ПМ, у кого бэклог в общих проектах ≥ порога.
- **Перегружены**: бэклог (`todo`) ≥ M (по умолчанию 8). «Кому отдать» — люди из «Нужны задачи» тех же проектов и роли.
- **Переключаются**: у человека есть задачи у двух руководителей, у одного всё в `todo` и ни одной в `wk/cr/rw`, у другого — движение.
- **Ресурсы по руководителям**: доля человека делится между руководителями пропорционально числу его задач в спринте (6 и 2 → 0,75 и 0,25). Уволенные и без исполнителя не считаются.
- **Узкие места**: незакрытые Blocked, Need Rework, «Требует уточнения» или без обновления > 30 дн.

## 4. Следующий спринт (`reference/sprints/ns_fetch.js`)
Имя текущего с номером +1 (`… 2026-19` → `… 2026-20`). «Перейдёт» = незакрытые текущего. «Без задач в следующем» = есть задачи в текущем, нет в следующем. Нет/пустой при `left ≤ 3` → красный.

## 5. Снепшот к созвону (`reference/snapshot/sprint_port.js`)
Исторический пересчёт по changelog (`expand=changelog`): статус и исполнитель «на момент t» = последнее изменение ≤ t.
- Ряд по дням спринта в 18:00: [в todo у руководителя, в todo без исполнителя, в todo у других, в работе/ревью/тесте, готово].
- `rwEv` — задачи спринта, уходившие в Need Rework после старта; `gave` — сколько раз руководитель переназначил задачу с себя.
- **Простой сотрудника**: рабочий день без отсутствия, на нём нет ни одной открытой задачи в спринте вне статусов ожидания (Test…Done). `none` — вообще без открытых задач; `quiet` — без активности в Jira; `cur` — текущая серия дней простоя.
- Бэклог вне спринта: открытые, не в спринте и не запланированные в ближайшие 14 дн. — на старте спринта и сейчас (всего / у руководителя / без исполнителя).

## 6. Посещаемость (`reference/attendance/build.py`, `page_template.html`)
Из событий `tgparse` + отпуска/БС Bitrix + больничные.
- Опоздание `late`: минуты `B − 540`. Ушёл раньше `early`: `1080 − A`. Отлучка `mid`: `B − A`. День `day`: 480.
- **Сумма** — сумма минут за период.
- **Позже заявленного** — `upd` пришёл позже заявленного времени прихода (B у `late`) более чем на 10 мин.
- **Полдня+** — дни, где отметки в сумме ≥ 240 мин.
- **Без согласования** — отсутствия ≥ 120 мин (кроме причины `study`), где нет `approved_by`.
- **Под конец спринта** — отпрашивался в последние 3 дня спринта проекта, где у него есть незакрытые задачи.
- **Отпуск / больн. / БС, дн.** — рабочие дни в отпуске, больничном или БС (Bitrix + Telegram).
- **Отработка** — время/дата из строки «отработка»; для отработки в списке показываем его открытые задачи (todo+wk+rw+Blocked) — если 0, «нечего делать».

## 7. Отсутствия на вкладке спринтов (`reference/absences/build_abs.js`)
Человек в отпуске/больничном/отпросился ≥ 2 ч за день, а на нём `todo/wk/rw` открытых спринтов. Метка «конец спринта» — отсутствие попадает на последние 2 дня спринта, где у него есть незакрытые задачи.

## 8. Нагрузка ПМов (`reference/pm/build_pm_load.py`)
По месяцам: задачи, где ПМ — автор (reporter): создано, из них внеплановых, закрыто, среднее время до закрытия, переназначения, доля возвратов в rework; сравнение со всеми ПМами. Выгрузка — Excel (`internal/export`).

## 9. Карточка сотрудника (`reference/employee/`)
Помесячно за год: задачи (создано/закрыто/в работе), время, плюс посещаемость (опоздания, минуты, дни отсутствия). Доступ — руководители и сам сотрудник.
Код: `internal/metrics/employee.go` (порт `build_emp.py`). Задачи — все, что обновлялись с начала года (`reports sync jira-history`); закрытая — текущему исполнителю в месяц закрытия; план спринта — задачи закрытых спринтов года, «в срок» — закрыта не позже 2 дней после конца спринта и не раньше его начала; возврат — переход в «Need Rework», засчитывается исполнителю на момент перехода; цикл — от первого выхода из «Бэклог/To Do/…» (или входа в «В работе») до закрытия, медиана.
