# Внешний API (только чтение)

REST API для получения данных отчётов во внешних системах (дэшборды, боты, BI): статистика по проектам, сотрудникам,
руководителям, тимлидам, тестировщикам, посещаемость, успеваемость, готовые списки и сводный дэшборд.

- Базовый адрес: `https://<сервер>/api/ext/v1` (у нас — `http://10.10.22.178:8081/api/ext/v1`)
- Swagger UI: `/api/ext/v1/docs`, спецификация OpenAPI 3: `/api/ext/v1/openapi.yaml` (открыты без токена — в них нет данных)
- Только `GET`. Формат — JSON, кодировка UTF-8.
- Спецификация — `internal/api/extdocs/openapi.yaml`; тест `TestExtSpecMatchesRoutes` следит, чтобы она не расходилась с маршрутами.

## Авторизация

Статичный токен. Передаётся заголовком:

```
Authorization: Bearer <токен>
```

или `X-API-Key: <токен>`. В query-параметре токен **не принимается** (попадает в логи прокси).

```bash
curl -H "Authorization: Bearer $TOKEN" http://10.10.22.178:8081/api/ext/v1/stats/summary
```

**Где взять токен.** Он задаётся переменной `EXT_API_TOKEN` в `deploy/.env` на сервере (`/opt/adata-reports/deploy/.env`, права 600).
Не задана — внешний API выключен (все пути с данными отвечают 404). Минимальная длина — 24 символа; сгенерировать:

```bash
openssl rand -hex 24
```

Смена токена: поменять значение в `.env` и перезапустить `api`: `sudo docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.local.yml --env-file deploy/.env up -d api`.

**Безопасность.**
- Токен даёт доступ ко **всем** данным, включая посещаемость и причины отсутствий (как роль admin). Хранить как пароль, выдавать только доверенным системам. Токен один на всех: при утечке его меняют сразу для всех систем.
- 20 неверных токенов за 10 минут с одного адреса → блокировка на 10 минут (`429`).
- Работайте по HTTPS/внутри корпоративной сети: на HTTP токен идёт открытым текстом.
- Причины отсутствий (`note`) и журнал посещаемости отдаются только по явному запросу (`reasons=true`, `/attendance/events`, `include=attendance_log`).

## Формат ответа

```json
{
  "meta": { "data_updated_at": "2026-11-17T09:41:00Z", "generated_at": "2026-11-17T09:50:12Z", "count": 31 },
  "data": [ ... ]
}
```

- `meta.data_updated_at` — когда в последний раз успешно синхронизирована Jira (данные спринтов не старше этого времени).
- `meta.count` — число элементов у списков.
- Даты — `YYYY-MM-DD`, часовой пояс Asia/Almaty; время в `meta` — UTC.
- Ошибки: `{"error": "..."}`. Коды: `401` нет/неверный токен, `404` не найдено (или API выключен), `429` слишком много неверных токенов,
  `503` данных ещё нет (не было синхронизации Jira), `500` внутренняя ошибка.

Обновление данных: Jira — раз в 30 минут в рабочее время (08:30–20:00 Алматы), полная синхронизация раз в сутки;
отпуска Bitrix — раз в 30 минут; сообщения Telegram — сразу.

## Эндпоинты

| Раздел | Метод и путь | Что отдаёт |
|---|---|---|
| Служебное | `GET /ping` | проверка токена и свежести данных |
| Статистика | `GET /stats/summary` | общая картина по текущим спринтам |
| | `GET /stats/performance` | успеваемость в целом за год (по месяцам) |
| Проекты | `GET /projects` | статистика по проектам со спринтом |
| | `GET /projects/{key}` | детали проекта: люди, тестировщики, узкие места, след. спринт |
| Сотрудники | `GET /employees` | нагрузка людей в спринтах, признаки «нужны задачи»/«перегружен», год |
| | `GET /employees/{id}` | карточка: нагрузка, показатели за год, отсутствия, задачи, журнал |
| Руководители | `GET /leads` | статистика по руководителям проектов |
| | `GET /leads/{name}` | детали + расчёт «Контроля спринта руководителей» |
| Тимлиды | `GET /team-leads` | тимлиды и их нагрузка |
| Тестировщики | `GET /testers`, `GET /testers/{name}` | загрузка тестировщиков |
| Посещаемость | `GET /attendance` | кто отсутствует; показатели по людям за период |
| | `GET /attendance/events` | отдельные записи посещаемости |
| | `GET /absences` | отпуска/больничные/БС на ближайшие дни |
| Списки | `GET /lists/need-tasks` | кому нужны задачи |
| | `GET /lists/overloaded` | кто перегружен бэклогом |
| | `GET /lists/long-in-work` | задачи долго в работе |
| | `GET /lists/long-in-test` | задачи долго на тесте |
| | `GET /lists/blocked` | заблокированные задачи |
| | `GET /lists/bottlenecks` | узкие места |
| | `GET /lists/low-sprints` | спринты с низким % закрытия |
| | `GET /lists/risks` | риски по проектам |
| | `GET /lists/creation-spikes` | всплески создания задач в спринте |
| Дэшборды | `GET /dashboards/sprints` | всё важное одним ответом (как экран ТВ) |

Полные схемы полей, параметры и примеры — в Swagger UI.

### Общие параметры

| Параметр | Где | Смысл |
|---|---|---|
| `q` | списки | поиск по подстроке (регистр не важен) |
| `limit` | списки задач/рисков | не больше строк |
| `project`, `lead`, `role` | `/employees`, списки | фильтры по ключу проекта, руководителю, части должности |
| `from`, `to` | посещаемость | период `YYYY-MM-DD`; по умолчанию — с начала текущего месяца по сегодня |
| `reasons` | посещаемость | `true` — показывать причины отсутствий |
| `include` | `/employees`, `/employees/{id}` | `id`, `year`, `tasks`, `attendance_log` — через запятую |
| `top` | `/dashboards/sprints` | строк в каждом списке (10) |

Имена людей в путях (`/leads/{name}`, `/testers/{name}`) — ФИО целиком, URL-кодированное: `/leads/%D0%A2%D0%B0%D0%B6...`.
Сотрудника в `/employees/{id}` можно указать логином Jira или числовым `id` (его отдаёт `GET /employees?include=id`).

## Что означают показатели

Формулы те же, что в отчётах сервиса (`docs/metrics.md`); пороги совпадают с экраном ТВ.

**Задачи (`tasks`)** — задачи активных спринтов: `backlog` — «Сделать», `in_progress` — «В работе», `code_review`, `rework` — Need Rework,
`testing` — все остальные статусы, кроме «Готово», `done` — «Готово», `bugs` — из них ошибок.

**Проекты.** `done_pct` — доля задач в «Готово». `sprint.time_pct` — доля прошедшего времени спринта; `days_left` меньше нуля — спринт просрочен.
`added_after_start` — создано после старта спринта, `unplanned` — задачи с планом «Внеплановая», `stale` — незакрытые без обновлений больше 14 дней.
`created_daily` — сколько задач создано в каждый день спринта (для графика «потока» новых задач).

**Сотрудники (нагрузка).** `queue` = бэклог + в работе + реворк — сколько человек ещё может взять.
- `need_tasks` — очередь ≤ 2 (порог — `need_threshold`), человек не в отпуске/больничном, активен в Jira, не тимлид, не ПМ/руководитель проекта, не QA.
- `overloaded` — бэклог ≥ 8 (`overload_threshold`), кроме тимлидов, ПМов и QA.
- Считаются только задачи активных спринтов (не будущих).

**Успеваемость (`year`, `/stats/performance`)** — помесячно за год:
`done` закрыто задач (месяц закрытия, текущему исполнителю); `planned` — план спринта (задачи закрытых спринтов года),
`planned_on_time` — закрыто не позже 2 дней после конца спринта, `on_time_pct` — доля в срок;
`reworks` — переходы в Need Rework, `rework_pct` — к закрытым; `cycle_days` — медиана цикла от первого выхода из бэклога до закрытия;
`reported` — создано как автор, `tested` — закрыто как тестировщик; `late`, `early`, `mid`, `day`, `sick`, `minutes` — отметки посещаемости.

**Посещаемость.** Типы записей: `late` — опоздание, `early` — ушёл раньше, `mid` — отлучка, `day` — целый день, `sick` — больничный, `vac` — отпуск, `upd` — «пришёл» после заявленного опоздания.
`absence_days` — рабочие дни (пн–пт, без праздников) в отпуске, больничном и без содержания за период.
Типы отсутствий: `vac` — отпуск, `bs` — без содержания, `sick` — больничный, `off` — отпросился.

**Тестировщики.** Люди из поля Jira «Тестировщик»: `tasks` — задач, `in_test` — из них в Test, `done`, `open`;
`waiting` по проекту — в Test сейчас в задачах текущего спринта (отчёт «Загрузка QA»).

**Списки «долго»** — из «Контроля спринта руководителей»: `long-in-work` — задача в работе от 5 дней **с момента, когда её взяли** (по истории Jira;
круги ревью и доработки счётчик не сбрасывают), `long-in-test` — в Test от 3 дней с последнего перехода, `blocked` — все Blocked.
Если проект у нескольких руководителей, задача выводится один раз.

**Низкий % закрытия (`low-sprints`).** Учитываются спринты, где прошло не меньше 20% времени. `bad` — готово меньше 30% или отставание от времени больше 25 п.п.;
`warn` — меньше 50% или отставание больше 10 п.п.

**Риски (`risks`).** Спринт не закрыт в срок (тревога), отстаёт на 25+ п.п. (важно), есть Blocked (внимание, от 3 — важно),
нет следующего спринта при ≤ 3 днях до конца (внимание). Сверху — самые тяжёлые.

**Всплески (`creation-spikes`).** День, когда в спринт проекта создано от 10 задач; `unplanned` — из них внеплановых.

## Примеры

```bash
H="Authorization: Bearer $TOKEN"; B=http://10.10.22.178:8081/api/ext/v1

curl -H "$H" "$B/projects?sort=done_pct"                       # проекты, самые отстающие первыми
curl -H "$H" "$B/projects/AC"                                   # детали проекта
curl -H "$H" "$B/employees?project=AC&include=year"             # люди проекта + показатели за год
curl -H "$H" "$B/employees/domarov?include=tasks"               # карточка сотрудника с задачами
curl -H "$H" "$B/lists/need-tasks?threshold=1"                  # кому срочно нужны задачи
curl -H "$H" "$B/lists/long-in-test?limit=20"                   # залежавшиеся на тесте
curl -H "$H" "$B/attendance?from=2026-11-01&to=2026-11-15"      # посещаемость за период
curl -H "$H" "$B/dashboards/sprints?top=5"                      # сводка для дэшборда
```

Python:

```python
import requests
r = requests.get(f"{B}/stats/summary", headers={"Authorization": f"Bearer {TOKEN}"}, timeout=30)
r.raise_for_status()
print(r.json()["data"]["done_pct"], r.json()["meta"]["data_updated_at"])
```

## Ограничения

- Данные спринтов — только по **активным** спринтам; будущие спринты в показатели текущего не входят (кроме `next_sprint` проекта).
- Проекты без активного спринта в `/projects` не попадают.
- Карточка сотрудника и `/stats/performance` считаются по ~23 тыс. задач года (с историей Jira); готовый расчёт кэшируется на минуту, первый вызов после перезапуска может занять несколько секунд.
- Задачи и ФИО — как в Jira; сопоставление сотрудников с Telegram — по справочнику сервиса (`/admin/tg`).
- Нет записи: API только читает данные.
