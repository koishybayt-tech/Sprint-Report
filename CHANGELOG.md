## 2026-11-02 — Bitrix: API отпусков
- Вместо `BITRIX_WEBHOOK_URL` — `BITRIX_VACATION_URL` (https://bitrix.avh.kz/api/v1/vacation_api.php) и `BITRIX_API_KEY`; конфиг, `.env.example`, docs.
- Табельный ID: часть email сотрудника в Jira до «@», для нетабельных email — колонка `tab_id` в `seed/employees.csv` (сейчас нужна vbakeev, adavletov). Миграция `00005`.
- `internal/bitrix`: запрос по каждому сотруднику, «Трудовой отпуск» → vacation, «Отпуск б/с» → unpaid, «Прерван» и больничные пропускаются; запись в `absences` (source=bitrix) с дедупом по external_id. Ключ маскируется в логах, ошибках и выводе.
- `reports bitrix probe --id <ID>` — сырой ответ API; `reports sync bitrix`; worker синхронизирует раз в `BITRIX_SYNC_EVERY` (2h).
- Разбор по настоящему ответу (`items[]`: `element_id`, `vocation_type`, `date_start`/`date_end` в ДД.ММ.ГГГГ, `status`); 404 «отпуска не найдены» = заявлений нет; в статистике синка — все встретившиеся типы и статусы.

## 2026-11-02 — Доступ из офисной сети по паролю
- `docker-compose.local.yml`: api и web слушают только 127.0.0.1; новый сервис `gate` (Caddy, `deploy/Caddyfile.lan`) на порту 80 с basic auth — коллеги открывают http://<IP компьютера>/ с общим логином и паролем (`LAN_USER`, `LAN_PASSWORD_HASH` в `.env`).
- Временная мера до входа через Telegram с ролями.

## 2026-11-02 — Авторизация и пользователи
- Вход по логину и паролю: таблица `users` (bcrypt), сессии в cookie `adata_session` (httpOnly, SameSite=Lax, 14 дней, в БД — только sha256 токена), миграция `00006`. Лимит: 5 неудачных попыток на логин за 10 минут.
- Все `/api` кроме `healthz` и `auth/*` требуют вход; «Спринты» — admin, lead, employee (не hr); управление пользователями — только admin. Последнего активного admin снять нельзя; блокировка и смена пароля закрывают сессии.
- `reports users add` — первый администратор. web: страница входа, верхняя панель с пользователем и выходом, «Настройки» (смена своего пароля; пользователи: создание с выдачей пароля один раз, роль, блокировка, сброс пароля).
- Общий пароль на шлюзе `gate` убран — вход через пользователей сервиса.

## 2026-11-02 — Telegram: история, бот, больничные и «отпросился»
- `internal/tgbot`: запись сообщений (raw всегда), поиск автора (Telegram ID → @username → ФИО в тексте → имя аккаунта; на корпусе 99,5 % верно, 0 ошибок), разбор `tgparse`, события в `attendance_events`; правка сообщения помечает прежние события superseded. Миграция `00007`.
- `reports import-telegram --file result.json` — история из экспорта Telegram Desktop; повторный импорт и сообщения, уже полученные ботом, не дублируются.
- worker принимает сообщения группы ботом (getUpdates) при `TG_BOT_TOKEN` и `TG_CHAT_ID`; повтор при ошибке — с нарастающей паузой.
- seed `tg_aliases`: сохраняется ФИО из сообщений; строки без логина Jira сопоставляются по имени.
- «Спринты»: больничные и «отпросился» из Telegram во вкладке «Отсутствия», дашборде и KPI; пересечения с отпусками Bitrix не дублируются; причины в отчёт не попадают (docs/security.md).
